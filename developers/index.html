DEVELOPERS / PROTOCOL

Integrate the control contract without inventing authority.

Use stable proposal and attempt identity, bounded grants, independent admission, truthful outcomes and explicit reconciliation.

CANONICAL CONTROL
PROPOSE→DECIDE→ALLOW / DENY / ESCALATE
ALLOW→GRANT→EXECUTION_STARTED→OUTCOME→RECEIPT
IDENTITY

Stable action and attempt IDs

Bind principal, domain, material hash and source-state reference. Changed material or stale context must fail closed.

RETRY

Do not retry unknown effects blindly

Retry only when non-application is proven, or when the owning durable mechanism proves the same identity cannot create a second effect.

UNKNOWN

Preserve uncertainty

UNKNOWN_EFFECT is non-final. Reconciliation observes the original attempt and preserves uncertainty until stronger truth exists.

FEDERATION

Projection is not authority

Validate field scope, purpose, provenance, freshness and expiry. The receiver then makes its own decision and, if allowed, its own grant.

STOP
ACTIVE EXECUTION→STOP→CONTAIN→SAFE STATE→RECONCILE→STOP RECEIPT

STOP is a control semantic, not a universal public HTTP endpoint. Each integration must bind STOP to its qualified interrupt path.
